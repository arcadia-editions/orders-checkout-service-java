# P-02 StockReleaseReason has no PAYMENT_VOID_FAILED

status: accepted A
found by: zenwave-test-scenarios, claude opus, 2026-11-25
flow: place-order-flow
blocks: cancelOrder for the void-refused cause; the orderCancelled outcome caused by PaymentVoidFailed

## Problem
releaseStock runs on PaymentVoidFailed
([place-order-flow.zfl:263](../../../arcadia-editions-architecture/business-flows/place-order-flow.zfl#L263)), and "the
type of the event that triggered this step sets the release reason". The cancellation notice must say when the void
was refused (PAYMENT_VOID_FAILED, line 325). But
[catalog-inventory-api/domain-model.zdl:74](../../../catalog-inventory-api/domain-model.zdl#L74) `StockReleaseReason`
only has PAYMENT_DECLINED, PAYMENT_RETRY_EXHAUSTED, PAYMENT_VOIDED, RESERVATION_EXPIRED. Order.cancellationReason
([orders-checkout-api/domain-model.zdl](../../../orders-checkout-api/domain-model.zdl), CancelOrderInput.reason)
carries that name.

## Evidence
No fixture can be written for an order cancelled because the void was refused: its cancellation_reason would be a value
the model doesn't have.

## Options
- A: add PAYMENT_VOID_FAILED to StockReleaseReason (catalog-inventory ZDL, its asyncapi.yml / Avro enum
  StockReleaseReason.avsc); regenerate; add the fixture chain.
- B: map PaymentVoidFailed to PAYMENT_VOIDED; the notice can't tell the customer the hold may still show.

Recommendation: A.

## Decision
Option A, 2026-11-25: PAYMENT_VOID_FAILED added to StockReleaseReason in the catalog-inventory-api ZDL (synced with the modulith); fixture chain C-10. Pending: push, regenerate the Avro enum StockReleaseReason.avsc and asyncapi.yml, new baseline.
