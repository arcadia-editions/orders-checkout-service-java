# P-01 confirmOrder cannot reject: no OrderConfirmationRejected, no NOT_HELD result

status: open
found by: zenwave-test-scenarios, claude opus, 2026-11-25
flow: place-order-flow
blocks: confirmOrder rejection tasks (stock-not-held, order-cancelled)

## Problem
The ZFL gives confirmOrder three outcomes
([place-order-flow.zfl:155](../../../arcadia-editions-architecture/business-flows/place-order-flow.zfl#L155)):
`confirmed`, `stock-not-held` (on StockReservationNotHeldResult, line 159) and `order-cancelled` (line 163), the last
two emitting OrderConfirmationRejected, which voidPayment consumes (line 246). The ZDLs cannot express the rejections:

- [orders-checkout-api/domain-model.zdl:133](../../../orders-checkout-api/domain-model.zdl#L133):
  `confirmOrder ... withEvents OrderConfirmed`. There is no OrderConfirmationRejected event and no channel in
  `asyncapi.yml`, and `@transition(from: CREATED, ...)` (line 131) leaves out the CANCELLED start state of
  `order-cancelled`.
- [catalog-inventory-api/domain-model.zdl:151](../../../catalog-inventory-api/domain-model.zdl#L151):
  `confirmStockReservation ... StockReservation[]` has no NOT_HELD response (the ZFL declares
  StockReservationNotHeldResult, line 175).
- payments-processing-api has no consumer for OrderConfirmationRejected, so a late authorization is never voided.

## Evidence
Fixtures ORD-005 (CREATED, stock released upstream) and ORD-006 (CANCELLED, RESERVATION_EXPIRED) in
`src/test/resources/data.sql` are the start states. A test can't assert OrderConfirmationRejected for either, because
the event doesn't exist.

## Options
- A: align with the modulith model (`arcadia-editions-modulith-api/orders-checkout-domain-model.zdl:109,178`):
  `confirmOrder withEvents [OrderConfirmed | OrderConfirmationRejected]`, the event with an `@asyncapi` channel
  (orderId, reason STOCK_NOT_HELD / ORDER_CANCELLED); confirmStockReservation returns a result wrapper with
  CONFIRMED / NOT_HELD (as ReserveStockResult does); payments-processing adds `@asyncapi` voidPayment on the new
  channel. Changes: 3 ZDLs, asyncapi.yml / asyncapi-client.yml of orders, inventory and payments, regenerated code;
  fixtures unchanged.
- B: drop both rejections from the ZFL (late authorizations stay authorized until they expire at the processor).
  Changes: ZFL only; loses the void of late holds.

Recommendation: A, it matches the modulith and the flow's no-charge promise.
